# Технический радар «Будущее 2.0»

Радар построен по кольцам зрелости внедрения (по аналогии с ThoughtWorks Tech Radar): **Adopt** — использовать по умолчанию, **Trial** — пилоты и ограниченный продакшен, **Assess** — изучение и POC, **Hold** — не расширять, планировать замену.

Графическое представление [технического радара](tech-radar.drawio.png)

Дополнительно для каждой позиции указано: **текущее (as-is)** / **целевое (to-be)** и **бизнес-сценарии**.

---

## Кольцо Adopt (закрепить и масштабировать)

| Технология / практика | As-is / To-be | Какие бизнес-сценарии поддерживает |
|----------------------|---------------|-----------------------------------|
| Облачная инфраструктура (IaaS/PaaS, управляемые сервисы) | To-be (ядро) | Масштабирование отчётности и пиков нагрузки; геораспределение; снижение CAPEX на железо |
| Разделение доменов и контракты данных (domain APIs, события) | To-be | Независимое развитие финтеха, ИИ и клиник; интеграция новых партнёров без прошивки монолита |
| Управление доступом и аудит (IAM, RBAC/ABAC, журналы) | Частично as-is → усилить to-be | Качество и соответствие требованиям по медицинским и финансовым данным; снижение репутационных и регуляторных рисков |
| Lakehouse / облачное аналитическое хранилище | To-be | Быстрая подготовка отчётности и витрин; единые KPI без прямого давления на операционные БД |

---

## Кольцо Trial (пилоты с измеримым эффектом)

| Технология / практика | As-is / To-be | Какие бизнес-сценарии поддерживает |
|----------------------|---------------|-----------------------------------|
| Портал самообслуживания (витрина данных, конструктор отчётов) | To-be | Самообслуживание аналитиков и бизнеса; ускорение принятия решений за счёт снижения очереди на IT |
| Семантический слой / метрики (dbt Semantic, Metric Layer и аналоги) | To-be | Согласованные показатели между BI и порталом; меньше споров о цифрах в управлении |
| Платформа потоковых событий (Kafka / аналог в облаке) | To-be (частично замена паттернов ESB) | Асинхронная интеграция новых финтех-сервисов и доменов; слабая связанность |
| Data Mesh (принципы: продукты данных, федеративная модель) | To-be (эволюция) | Масштабирование на новые бизнесы и партнёров без централизации всей логики в DWH |
| CDC и оркестрация (Airflow / Managed Workflow, Debezium и т.д.) | To-be | Актуальные витрины без ночных «полных срезов»; разгрузка легаси-DWH |

---

## Кольцо Assess (оценка, POC, выбор стека)

| Технология / практика | As-is / To-be | Какие бизнес-сценарии поддерживает |
|----------------------|---------------|-----------------------------------|
| Замена/сужение роли Apache Camel (ESB) в пользу API Gateway + события | To-be | Time-to-market интеграций; снижение операционных затрат на поддержку шины |
| MLOps для ИИ-сервисов (реестры моделей, воспроизводимость) | Частично as-is (Python) → усилить | Качество и предсказуемость ИИ-сервисов в клиническом контуре (в рамках политики) |
| Feature Store (при росте ML в продакшене) | Assess | Ускорение вывода моделей и согласованность признаков для медицинских сценариев |

---

## Кольцо Hold (не развивать; выводить)

| Технология / практика | As-is / To-be | Почему на Hold и какие сценарии страдают, если не мигрировать |
|----------------------|---------------|----------------------------------|
| Расширение бизнес-логики в SQL Server 2008 DWH | As-is | Тормозит TTM; риски поддержки и ИБ; мешает независимому развитию доменов |
| Прямой тяжёлый ad-hoc из BI в монолитный DWH | As-is | Часы на отчёты; конкуренция с операциями; ошибки в управленческих решениях из-за задержек |
| PowerBuilder как долгосрочная стратегия UI | As-is | Высокая стоимость изменений; ограничение найма; сценарии клиники зависят от узкого стека |

---

## Сводка: методологии

| Методология | Кольцо | Бизнес-сценарии |
|-------------|--------|-----------------|
| DevOps / GitOps в облаке | Trial → Adopt | Скорость релизов финтеха и платформы данных |
| FinOps (учёт и оптимизация облачных затрат) | Trial | Снижение затрат при росте объёмов данных и вычислений |
| Data Governance (владельцы данных, глоссарий, качество) | Trial | Доверие к отчётам; комплаенс для банка и медицины |
